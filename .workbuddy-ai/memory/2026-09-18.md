### P0 三个实验（结论写入 `docs/spikes.md`）

1. **Dock 重载策略**：A（post 通知，darwin 与分布式两种都试了）**彻底无效**；B（SIGHUP）生效但**是进程重启不是热重载**，总不可用约 **101 ms**；C（SIGTERM）Dock 会先做约 255 ms 清理，总不可用约 **367–395 ms**。→ **主路径定为 SIGHUP，SIGTERM + kickstart 兜底**。
2. **主动切桌面**：`CGSManagedDisplaySetCurrentSpace` 可用，约 **20 ms** 生效。**但程序化切换不触发 `NSWorkspaceActiveSpaceDidChangeNotification`**（用对照实验排除了环境因素：同进程能正常收到 `didActivateApplication`）。→ 事件源主次反转为**轮询为主（300 ms）**，自己发起的切换必须预应用。
3. **Finder**：全量域 34 个键里没有任何 Finder 相关键或值，`persistent-apps` 中也没有 → 写偏好无法删除它，钉住天然成立，无需代码。

**关键技术手段（无系统权限下的客观判据）**：写入的 tile 故意不带 `GUID`，Dock 真正读取并应用后会**补上 GUID** —— 这是判断"Dock 到底有没有应用写入"的决定性信号（正负两种情形都验证过）。另外本机**未授予屏幕录制权限**，`screencapture` 只返回壁纸，不能用截图验证。

### 踩到的坑（下次别再踩）

- `screencapture` 无屏幕录制权限时只返回壁纸，**不要用它做验收**。
- `find` 在本机被 `fd` 之类的工具遮蔽，`-path/-type f` 参数会报错；用 Glob 工具代替。
- 顶层 `let` 引用 `private` 的 `@convention(c)` 函数指针类型会报 "uses a private type"，必须也标 `private`。
- 清理 `.build` 会被 safe-delete 保护拦截；要全新构建用 `--build-path /tmp/...`。
- `log show` 默认不显示 info 级日志，需要 `--info`（本机沙箱下则完全不可用）。
- 本机 `_HIHideMenuBar = 1`，状态栏窗口出现在 `y=-24`、`onscreen=false` 是正常的。

## 追加：计划新增「桌面命名 + 切换 toast」（只改文档）

用户需求：**设置 → 桌面里能给每个桌面起名，最长 10 个字符；切换桌面后在屏幕中上部弹 toast 显示该名字，1 秒后自动消失。**

**本轮只更新文档，没写业务代码**（用户原话是"更新计划"）。

### 设计要点（写进 `docs/PLAN.md` §3.10）

- 名字存 `DesktopBinding.customName`（**该字段早就存在，P1 已建模**），只存本地 `config.json`；改名**不创建 Dock override**，与绑定解耦。
- 10 个字符按**字素簇**（`String.count`）计；**两层防线**：输入框截断 + 模型层 `normalizeDesktopName` 归一化（防手改 config.json 撑破布局）。
- **名字解析统一走 `AppState.displayName(for:)`**，必须替换所有 `DesktopSpace.displayName` 调用点（MenuBarController / 日志 / SettingsView / DebugPanelView），漏一处名字就不一致。
- toast **触发点只有 `SpaceObserver.onActiveSpaceChanged`** 一个（轮询与切换来源无关 → 用户手动切桌面也会弹）；只在「用户桌面 → 另一个用户桌面」时弹，这样**启动不弹、从全屏 App 退回桌面不弹**。
- 窗口属性是成败关键：`collectionBehavior` 必须含 **`.canJoinAllSpaces` + `.fullScreenAuxiliary`**（少了就只在自己所在空间显示，切过去反而看不见）；`canBecomeKey = false` + `ignoresMouseEvents = true`（绝不抢焦点/挡点击）；`level = .statusBar`（25，高于 Dock 的 layer 20）；用 `orderFrontRegardless()` 显示。
- 连击切桌面：**换文字 + 重置计时**，绝不并发多个计时器。
- **零系统权限**，符合硬约束。

### 新增的实测事实（已跑通并入库）

`CGDisplayCreateUUIDFromDisplayID(NSScreen.deviceDescription["NSScreenNumber"])` 与 SkyLight 的 `Display Identifier` **逐字符相同**（都是 `AB24BB32-C5EC-D10A-6F9D-F01F35552F60`）→ toast 能定位到正确的显示器，原本的未知项消掉了。主屏 `frame` 1920×1200、`visibleFrame` (0,53,1920,1147)。已把 `screens` 段加进 `scripts/spike-probe.swift`（文本 + `--json` 双输出）。

### 无截图的验收手法（沿用 P1 思路）

用 **`CGWindowListCopyWindowInfo`** 读窗口元数据（layer / alpha / bounds）——**不需要屏幕录制权限**，只有抓图 `kCGWindowImage` 才需要。计划里定了 `scripts/check-toast-window.sh` + 调试面板「测试 toast」按钮 + `multidock.log` 记"显示/隐藏"两行来核对 1 秒。
