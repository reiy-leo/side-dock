### P0 三个实验（结论写入 `docs/spikes.md`）

1. **Dock 重载策略**：A（post 通知，darwin 与分布式两种都试了）**彻底无效**；B（SIGHUP）生效但**是进程重启不是热重载**，总不可用约 **101 ms**；C（SIGTERM）Dock 会先做约 255 ms 清理，总不可用约 **367–395 ms**。→ **主路径定为 SIGHUP，SIGTERM + kickstart 兜底**。

3. **Finder**：全量域 34 个键里没有任何 Finder 相关键或值，`persistent-apps` 中也没有 → 写偏好无法删除它，钉住天然成立，无需代码。

### 三个值得记住的技术结论

1. **`orderOut` 之后窗口会在 CG 窗口列表里滞留好几秒**：`kCGWindowIsOnscreen` 立刻变 false，但记录还在。用窗口元数据核对"消失"时刻**必须滤 `onscreen`**，否则时长晚报。
2. **`CGWindowListCopyWindowInfo` 在无屏幕录制权限下能读到 layer / alpha / bounds / onscreen，但读不到 `kCGWindowName`**。所以浮层窗口的验收完全不需要权限；判别自己的窗口用「layer 25 + 高度 ≥ 30 + 水平居中」（菜单栏图标在角落，天然排除）。
3. **`CGDisplayCreateUUIDFromDisplayID(NSScreen.deviceDescription["NSScreenNumber"])` 与 SkyLight 的 `Display Identifier` 逐字符相同** → 能把浮层放到正确的显示器上。

### 踩到的坑（下次直接绕开）

- **Swift 脚本 stdout 重定向到文件时是块缓冲** → 观察类工具必须 `setvbuf(stdout, nil, _IONBF, 0)`，否则一行都看不到。
- **反复调用的探测工具要 `swiftc -O` 编译一次缓存复用**：每次 `swift file.swift` 都是完整编译（5–10 s），几十毫秒级轮询跑不动。第一次的采样窗口就是被编译时间吃掉的，测试白跑。
- **后台任务必须和前台等待放在同一条 shell 调用里**（`cmd & ... wait`），跨调用的后台进程会被清掉。
- **`AppSettings` 加字段必须同步补手写 `init(from:)` 里的 `decodeIfPresent`**：合成解码器遇到旧配置缺键会抛错，而 `ConfigStore.load()` 失败返回**整份默认配置** → 用户设置被静默清空。
- **改名输入框不要边打字边截断**：中文输入法组字期间改写绑定值会打断候选词。草稿留本地 `@State`，回车/失焦时归一化。

真实改 `com.apple.dock` + 重启 Dock，跑完自动还原：

### 值得记住的技术结论

1. **Dock 回写 `GUID` 是异步的**：`apply` 返回后立刻读还是 `nil`，轮询 200 ms 内出现。拿它当判据必须配轮询，否则会误判成「写入没生效」（第一轮验收就这么误报的）。
2. **Dock 重启一次，`mod-count` 就 +1，`recent-apps` 也会变**。这两个不在白名单里、我们从不写 → 验收判据要放宽成「差异只能落在白名单键或 `{mod-count, recent-apps, trash-full}` 上」。
3. **本机白名单键可用性已逐键实测**：只有 `show-process-indicators` 缺失；`autohide-delay` / `autohide-time-modifier` 域里没有、读回来是 nil 压根不进写入集合。→ **「只写域里已有的键」这条规则就够了**。
4. **`.app` 的 `_CFURLString` 必须带尾斜杠**（`file:///Applications/X.app/`），`URL.absoluteString` 不带。用户 App `dock-extra=true`、启动台 `file-type=169` + `dock-extra=false`。
5. **`plutil -p` + `diff` 比对长数组会错位**，产生假差异。判断「成员/顺序」抽标签序列比，判断「值」用结构化比较。

- **无条件退出还原会抹掉用户自己拖的图标** → 加 `sessionChangedDock` 门槛（只在会话标记里 `appliedFingerprint != nil` 时还原），并且「已与基准一致就跳过」（省一次没必要的 Dock 重启）。

- **`DockStripRules.normalizedApps` 一开始无条件重建启动台条目**，把真实域里的 `GUID`/`book`/`file-mod-date` 抹掉了。改成优先复用已有条目。

1. **launchd 的重启节流**。P3 第一次跑验收时每轮耗时约 1080 ms（P0/P2 测的是 101/125–138 ms），差了近 10 倍。查下来：**距上一次重启不足约 1 秒时再次重启，Dock 要约 1070 ms 才归位；间隔 ≥ 1 秒只要约 70 ms**（阈值在 0.6–1.0 s 之间）。`com.apple.Dock.plist` 里没有 `ThrottleInterval`，是 launchd 的隐式节流。
   → `DockReloader.minimumSpacing`（默认 1 s）：距上次**归位**不足 1 秒就先等满再重启。**等待期间 Dock 是活的、可用的**，所以"等"严格优于"立刻重启"。实测把 Dock 不可用时长从约 1030 ms 压到 **45–90 ms**。
   → `ReloadOutcome` 把 `elapsed`（真不可用）与 `spacingWait`（可用等待）分开记，否则日志里会出现"用时 1070 ms"这种吓人但误导的数字。

2. **`NSRunningApplication` 会返回 `processIdentifier == -1`**。写探测脚本时打印出 `48100 → -1`。`runningApplications(withBundleIdentifier:)` 在 Dock 重启窗口里会返回一个**正在退出**的实例，PID 就是 -1。
   危害：① `waitForRestart` 看到 `-1 != oldPID` → 立刻"成功"，`ReloadOutcome` **谎报 Dock 已回来**；② 兜底路径 `dockPID() ?? oldPID` 拿到 -1 → **`kill(-1, SIGTERM)`**，而 `kill(-1, sig)` 的语义是**发给当前用户的全部进程** —— 能毁掉用户整个图形会话。`kill(0, sig)` 同理（整个进程组）。
   修复（三道防线）：`dockPID()` 过滤 `!isTerminated && pid > 0`；`RealDockProcessControl.signal()` 拒绝 `pid <= 0` 并用 `proc_name` 确认进程名真的是 `Dock`；`waitForRestart` 只接受 `pid > 0`。
   测试在 `DockProcessSafetyTests`，**全部用信号 0（空信号）断言** —— 这样闸门万一被改坏，测试是失败而不是把测试进程自己打死。

### 顺带修掉的性能浪费

`pgrep` 子进程单次 **110 ms**，被放在 15 ms 一轮的轮询热路径里当 `NSRunningApplication` 的兜底。换成 `proc_listpids(PROC_ALL_PIDS)` + `proc_name`（**0.02 ms**，libproc，直接调）。注意这**不是**那 1 秒的真因，但是真浪费。

### 本次最值钱的发现：节流是"按 launchd 服务"算的，不是按"你的对象"算的

P4 验收里有一条真实 Dock 用例直接报：

```
XCTAssertLessThan failed: ("1.0306010246276855") is not less than ("0.3")
- 第 1 次 Dock 不可用 1030 ms，节流没被错开
```

**不是测试写错了，是真 bug。** 原来把"上次重启时刻"记在 `DockReloader` 实例的 `lastRestartAt` 里。
上一个用例刚重启过 Dock，下一个用例**新建的 reloader** 看到 `lastRestartAt == nil` → 立刻重启 → 吃满节流。

危害的现实对应：**用户（或别的 App、或我们自己的 presence monitor）刚重启过 Dock，紧接着我们切桌面，Dock 会消失一秒多。**

修法：改成读 **Dock 进程的真实启动时刻**，算年龄，`age >= 1s` 才动手。

```swift
var info = proc_bsdinfo()
let size = MemoryLayout<proc_bsdinfo>.size          // 实测 = 136
let written = proc_pidinfo(pid, PROC_PIDTBSDINFO, 0, &info, Int32(size))
guard written == Int32(size) else { return nil }
return TimeInterval(info.pbi_start_tvsec) + TimeInterval(info.pbi_start_tvusec) / 1_000_000
```

**留退化路径**：拿不到年龄（PID 刚死）就退回内存里的 `lastRestartAt`；两者都没有就别等。

效果：P3 验收第 1 轮 **1030 ms → 45 ms**，最坏 84 ms。补了 4 条回归测试钉住
（`testFreshReloaderStillWaitsWhenTheDockIsYoung` 等）+ 1 条"真实 Dock 启动时刻读得到"的守卫。

> 教训：**判据要锚在外部客观事实（进程年龄）上，不要锚在自己的记账上。** 只要系统状态能被
> 别人改变，自己记账就一定会漂。这条已写进 `macos-dock-space-probe` skill。

### 其余技术结论

- **`kill -9` 掉 Dock → 约 1072 ms 被 launchd 拉回**（含一次隐式节流）。所以 presence monitor 的超时判据要按秒级放宽，且**连续 2 次探不到才动手**，否则会把"正常重启窗口里的瞬时缺失"当成崩溃。
- **自愈欠账必须跨会话存活**：`SessionMarker.needsSelfHeal` 用**可选字段**（旧的 `session.state` 还能解码）；`beginSession()` 把上一次的欠账继承进新标记。
- **还原失败时要保留标记、并把会话置为"非活跃"**：`needsSelfHeal = true` + `pid = 0`。`pid = 0` 是关键 —— `detectInterruptedSession()` 用 `kill(pid, 0)` 判断"是否还有活着的实例"，只有 `pid == 0` 才会跳过这个检查。
- **退出还原前必须排空待办**：`await state.prepareForTermination()`（停 watcher + 停 presence monitor + 等自愈 + `await dockController.waitForIdle()`）。不排空的话，排队中的 apply 会落在还原**之后**，把 Dock 又弄脏。
- **备份还原只写白名单键**，绝不做整域替换（否则会把用户的热角、Launchpad 网格一起回退掉）。
- **`mru-spaces` 是白名单之外的唯一写入例外**，给它一个只认这一个键的专用方法（不是通用写入器）；它不在 `apply` 的管辖里，所以另配一个 `reloadOnly()`。
- **`SMAppService.mainApp` 只能在真 `.app` 包里用**：`swift test` 没有 bundle → `LoginItem.isAvailable` 先查 `Bundle.main.bundlePath.hasSuffix(".app")`，如实报原因而不是假装成功。
