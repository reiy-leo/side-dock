## 第 22 轮 — 挖出取证仪表的致命 bug + 证伪第六个假说（LS 滞后）

**① 仪表在生产路径上完全是死的（本轮最值钱的发现）。** 给上一轮装的 A8 取证仪表写真机验收测试，
第一条断言就炸：`XCTUnwrap failed: expected non-nil value of type "DockPIDProbe"`。

根因是 Swift 的**协议见证位协变陷阱**：协议要求 `func pidProbe() -> DockPIDProbe?`，扩展里有
默认实现 `{ nil }`，而 `RealDockProcessControl` 写的是**非可选** `-> DockPIDProbe`。
Swift 不做返回类型协变匹配 → 具体方法被当成**另一个重载**，协议要求的见证位**由默认实现满足**：

```swift
RealDockProcessControl().pidProbe()                                   // ✅ 有值
(RealDockProcessControl() as any DockProcessControlling).pidProbe()   // ❌ nil
```

`DockReloader` 持有的正是 `any DockProcessControlling` → `sample()` 里 `guard let probe = … else { return }`
每次直接返回，时间线恒为空。**6 条替身单测全绿，因为替身自己签的就是 `T?`。**

→ **教训：替身单测证明不了生产路径接通。有默认实现的协议要求，必须补一条走 `any` 协议调用的守卫测试。**

**② 那条验收测试自己有竞态。** 阈值写 `1 ms` 时实测**一次空、三次有** —— 探测机会在**第二轮**轮询，
而 `dockPID()` 的判定排在 `sample()` **之前**，只要 `Task.sleep(15 ms)` 被拖长、Dock 在那之前回来，
就会先返回、一条不记。改成 `.zero` 后连跑 4 次，每次稳定 2 条：

```
慢重启取证：0ms LS=72409 scan=nil｜36ms LS=nil scan=72516
```

**③ 这一行产出新线索 → 定向测量 → 第六个假说证伪。** 新增
`scripts/measure-launchservices-lag.swift`（只读 + SIGHUP），1 ms 采样同时问两条路径，6 轮：

| 量 | 实测 |
| --- | --- |
| 进程表看到新 PID | 26–33 ms |
| LS 松手（不再报旧 PID） | **11–29 ms** |
| LS 看到新 PID | 70–93 ms |
| **危险窗口（进程表已知新、`dockPID()` 还报旧）** | **6/6 = 0 ms** |

机制上也不成立：LS **松手早、认领晚**，而 `dockPID()` 是 **LS 优先 + nil 回退扫进程表**，
回退把那半段完全吃掉。→ **A8 的"我们的 bug"候选至此清空。**

**④ 全量回归**：`swift test --disable-sandbox` → **316 个测试、8 跳过、0 失败**；

## 第 23 轮 — 更正我自己的一处过度概括 + 补上"我们没在看"这个洞

App 没在跑、`multidock.log` 无新增（仍 3164 行）→ 没有新的 A8 偶发。于是回头**逐字复核**
11.6 / 15 里那句"主线程是活的、不是假测量"，**发现它站不住**：

```
05:32:18.675  第一笔 apply 开始（= 44.735 − 26.060 s）
05:32:20.566  toast 显示 → 21.597 隐藏      ← 1.03 s，准时，共 4 组
05:32:27.364  toast 显示 → 28.388 隐藏      ← 最后一组证据
              ↓ 16.35 秒完全空白
05:32:44.735  Dock 应用成功：Dock 不可用 26046 ms
```

toast 证据只覆盖窗口的**前 10 秒**；后 16.35 秒毫无存活性证据。而那段空白两种解释都成立
（Dock 真的不在 / 主线程被冻住 —— `DockPresenceMonitor` 在重载期间本来就被 `guard !isReloading()` 静音）。

**洞是结构性的**：`waitForRestart` 的 `elapsed` 是**墙钟**，而轮询循环跑在 `@MainActor` 上 ——
主线程被冻住时循环跑不动，我们**根本没在看**，却照样把整段时间记成"Dock 不可用"。
**"Dock 慢"与"我们瞎了"在旧日志里长得一模一样。**

修法：每轮记**轮询次数 + 最长间隔**，跟着慢重启那一句日志出来：

```
… Dock 不可用 26046 ms；轮询 1738 次，最长间隔 18 ms；慢重启取证：…
```

- 次数 ≈ `elapsed / 15 ms`、最长间隔十几毫秒 → **一直在看**，Dock 真的不在（launchd 侧）；
- 次数远低、最长间隔**秒级** → **观察窗口断了**，是我们的 bug。

只在 `elapsed > 1` 时记 → 快路径日志行一个字节不变。新增单测 3 条，关键那条让**替身在第 3 次
`dockPID()` 上阻塞 80 ms**，断言最长间隔体现出来并与未阻塞的对照；为让 `elapsed` 真过 1 秒，
`makeProbingReloader` 加了 `timeout` / `pollInterval` 参数。

**教训（值得记住）**：任何"某段时间里 X 没发生"的结论，都要先问一句 ——
**那段时间里，我有能力观察到 X 吗？** 观测者自身的存活性也是证据的一部分。
